# SWU Deck Builder 0.2.0 — Desktop everywhere

SWU Deck Builder 0.2.0 brings the local-first desktop app to macOS and Linux while continuing to support Windows. The full deck-building experience from 0.1.0—including the local deck library, catalog search, format checks, SWUDB import and export, and optional AI Deck Assistant—is now packaged for all three major desktop platforms.

[Open the hosted app](https://swu.wuteri.ch/) · [View the project on GitHub](https://github.com/Alfwich/swu-deck-builder)

## What's new since 0.1.0

| | 0.1.0 | 0.2.0 |
| --- | --- | --- |
| Desktop platforms | Windows x64 | Windows x64, universal macOS, and Linux x64 |
| Release downloads | Windows installer | Windows installer, macOS DMG and ZIP, Linux DEB and RPM |

## Native macOS and Linux apps

The desktop app is no longer Windows-first. Version 0.2.0 adds:

- A universal macOS DMG that runs natively on Apple Silicon and Intel Macs.
- A macOS ZIP for archive-based installation and distribution.
- A DEB package for Debian, Ubuntu, and related Linux distributions.
- An RPM package for Fedora, RHEL, and related Linux distributions.

Every desktop edition keeps decks in a local SQLite database beneath the operating system's per-user application-data directory. Desktop settings live there too, so installing a newer application build does not replace your deck library or AI provider preferences.

## Better local AI setup on macOS and Linux

The optional Deck Assistant can still use a Codex or Claude CLI authenticated on your computer. In 0.2.0, the desktop app also searches the locations commonly used by Homebrew, user-local installs, npm global installs, and Volta on macOS and Linux. This makes a CLI launched successfully from your terminal more likely to work in the packaged app without an executable-path override.

If automatic detection does not find your CLI, **Desktop settings** still lets you choose a provider and enter its executable path directly. Using Codex or Claude may consume the allowance associated with the account authenticated in that CLI.

## More reliable release packaging

Desktop packages now carry native icon formats and platform metadata instead of relying on the Windows-oriented asset path used in 0.1.0. Published releases are built independently on Windows, macOS, and Linux, and each platform job runs the project's automated tests and lint checks before uploading its artifacts.

This release does not change the local-first model: the hosted app keeps decks in the current browser profile, while desktop builds keep them on the local computer. AI access remains optional and disabled when no provider is configured.

## Get 0.2.0

Download the package for your platform from the **Assets** section below:

- **Windows x64:** `SWU Deck Builder-0.2.0 Setup.exe`
- **macOS, Apple Silicon or Intel:** the universal `.dmg`; use the `.zip` if you prefer an archive
- **Debian or Ubuntu Linux x64:** the `.deb` package
- **Fedora or RHEL Linux x64:** the `.rpm` package

Existing desktop users can install 0.2.0 over their current application. Decks and desktop settings remain in the per-user data directory rather than the installation directory.

Prefer the browser? The latest hosted version remains available at [swu.wuteri.ch](https://swu.wuteri.ch/), with no installation required.
