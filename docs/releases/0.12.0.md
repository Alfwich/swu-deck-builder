# SWU Deck Builder 0.12.0 — Deck composition at a glance

SWU Deck Builder 0.12.0 expands the deck summary with responsive card-type and cost charts, makes assistant resizing more predictable, and gives local AI CLI requests more time to finish.

[Open the hosted app](https://swu.wuteri.ch/) · [View the project on GitHub](https://github.com/Alfwich/swu-deck-builder)

## Highlights since 0.11.0

### See the main-deck mix instantly

A new pie chart beside the cost curve shows how the main deck is divided among **Units**, **Events**, **Equipment**, and **Other** cards. Catalog upgrades are included in the Equipment segment, and a visible legend provides exact counts for every category.

The composition chart uses the same scope as the cost curve: draw-deck cards are counted, while leaders, bases, and sideboard cards are excluded. Both charts include text summaries for assistive technology and reorganize into a stacked layout on narrow screens.

### A more interactive cost curve

The existing cost curve now uses Chart.js alongside the new composition chart. Counts remain visible above every cost bucket, while pointer tooltips provide the corresponding card totals. The average cost and nominal deck value remain in the summary header.

### More predictable assistant controls

Manually resizing the AI deck assistant no longer changes the selected **Small** or **Large** mode. Dragging the resize handle or using its keyboard controls preserves the current mode, so future openings continue to use the preference the player selected.

The assistant header is also simpler: the redundant **New** session button has been removed, leaving the size controls and close button together.

### Ten minutes for AI CLI responses

The default Codex and Claude CLI invocation timeout increases from two minutes to ten minutes. This gives longer deck-building, collection, image, and research requests more time to complete before the server stops the provider process.

The timeout remains server-wide and configurable with `AGENT_CLI_TIMEOUT_MS`. Existing installations that explicitly set the previous `120000` value keep that override until an administrator changes it to `600000` and restarts the service.

## Upgrading from 0.11.0

Install version 0.12.0 over the existing desktop application. Saved decks, owned cards, prompt history, assistant size preferences, desktop AI settings, provider preferences, and database backups remain compatible.

No deck or collection migration is required. Server administrators who want the new ten-minute CLI limit should set `AGENT_CLI_TIMEOUT_MS=600000` in the service environment and restart the service; deployments intentionally preserve existing environment files.
