# SWU Deck Builder 0.4.0 — Card libraries, image-aware AI, and easier purchasing

SWU Deck Builder 0.4.0 adds a local card library, gives the Deck Assistant safe tools for managing owned cards, supports image attachments with Codex in the desktop app, and can prepare TCGplayer Mass Entry lists for a complete deck or only the cards still missing.

[Open the hosted app](https://swu.wuteri.ch/) · [View the project on GitHub](https://github.com/Alfwich/swu-deck-builder)

## What's new since 0.3.0

### Track the cards you own

The new card library is available from the right side of the deck builder without permanently taking up workspace. Search the catalog to add a card, then adjust its owned quantity with compact increase, decrease, and remove controls. The main fuzzy card search also offers **Add to collection** when the selected printing is not already represented.

Collection data remains local to the app. Decks that are fully covered by the library receive a positive **All cards owned** indicator; incomplete decks are not given negative or blocking warnings. Equivalent reprints count toward ownership so players are not required to own the exact printing used in a deck list.

### Let the Deck Assistant update the library

Codex, Claude, and OpenAI-backed assistant flows now receive the current card library as authoritative context. When explicitly asked, the assistant can propose adding or removing owned cards alongside ordinary deck changes. Collection operations use the same review flow as deck edits, validate card IDs and quantities, reject excess removals, and remain unapplied until the player accepts them.

### Attach or paste images in the desktop Deck Assistant

The Electron app can attach PNG, JPEG, or WebP images to Codex conversations through either the image picker or clipboard paste. Attachments are validated, staged in the writable per-user application-data directory, and removed after the request. Image controls are shown only when the active desktop provider supports them; the hosted web app and unsupported providers do not display an inactive control.

### Copy deck purchases into TCGplayer Mass Entry

The top deck actions now include a split **Copy TCGplayer list** control and a direct link to TCGplayer Mass Entry. The copied list includes leaders, bases, draw-deck cards, and sideboard cards in TCGplayer's quantity/name/set/number format.

Toggle the right-side **Missing only** segment to subtract the current card library before copying. Owned quantities and equivalent reprints are included in that calculation, making it easy to search for only the cards needed to finish a deck.

### Cleaner controls on unsupported platforms

Dictation is now omitted entirely in Electron and in browsers without speech-recognition support. Supported web browsers retain dictation, while desktop users no longer see a disabled button or an unavailable-feature message.

## Upgrading from 0.3.0

Install version 0.4.0 over the existing desktop application. Saved decks, desktop AI settings, and provider preferences are preserved. The card library starts empty and is stored locally as it is populated.

## Get 0.4.0

Download the package for your platform from the **Assets** section below:

- **Windows x64:** `SWU Deck Builder-0.4.0 Setup.exe`
- **macOS, Apple Silicon or Intel:** the universal `.dmg`; use the `.zip` if you prefer an archive
- **Debian or Ubuntu Linux x64:** the `.deb` package
- **Fedora or RHEL Linux x64:** the `.rpm` package

Prefer the browser? The latest hosted version remains available at [swu.wuteri.ch](https://swu.wuteri.ch/), with no installation required.

## Notes

- Windows and Linux packages currently target x64 systems.
- The macOS package is universal and supports both Apple Silicon and Intel Macs.
- Windows and macOS builds may not yet be code-signed, and macOS builds may not be notarized. Your operating system can display a publisher or trust warning during installation or first launch.
- Image attachments are currently limited to the Codex provider in the Electron app.
- Codex and Claude integrations use the account authenticated in the selected CLI and may consume that account's subscription allowance.
