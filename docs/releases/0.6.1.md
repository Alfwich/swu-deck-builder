# SWU Deck Builder 0.6.1 — Card library persistence fix

SWU Deck Builder 0.6.1 is a desktop bug-fix release that makes owned-card collections durable across Electron restarts and keeps the Card Library drawer clear of the native window controls.

[Open the hosted app](https://swu.wuteri.ch/) · [View the project on GitHub](https://github.com/Alfwich/swu-deck-builder)

## Fixes since 0.6.0

### Card libraries now survive desktop restarts

The Electron app now stores the Card Library in its local SQLite player database alongside saved decks. Previously, owned cards were written only to browser storage tied to the desktop app's temporary loopback origin, so the collection could appear empty after restarting the app.

Deck and collection changes are now saved together as one revisioned database snapshot. Existing browser-stored collection data is migrated into the database when it is still available, and database export and import continue to include the collection.

Collections that were already lost before installing this update cannot be recovered automatically. Add those cards once more after upgrading and subsequent launches will retain them.

### Card Library no longer conflicts with window controls

The desktop Card Library drawer now receives Electron layout state directly through its portal. It opens below the native title-bar area, leaving the minimize, maximize, and close controls unobstructed and keeping the library header and close action fully visible.

The hosted web layout is unchanged.

## Upgrading from 0.6.0

Install version 0.6.1 over the existing desktop application. Saved decks, desktop AI settings, provider preferences, and any collection data still available for migration are preserved. The player-database backup format remains at schema version 1.
