# SWU Deck Builder 0.9.1 — Multi-image collection proposal fix

SWU Deck Builder 0.9.1 fixes a card-library conflict that prevented more than one proposal from a multi-image Deck Assistant upload from being applied.

[Open the hosted app](https://swu.wuteri.ch/) · [View the project on GitHub](https://github.com/Alfwich/swu-deck-builder)

## Fixed since 0.9.0

### Apply every card from a multi-image upload

When several card images are queued, the Deck Assistant continues to inspect them one at a time and creates a separate reviewable proposal for each image. Applying the first card-library proposal now safely advances the remaining untouched proposals from that same upload batch, allowing them to be applied in sequence.

The stale-change safeguard remains active. Proposals from earlier uploads, different batches, or proposals made stale by an unrelated library edit are not advanced and still require the assistant to update them before they can be applied.

## Upgrading from 0.9.0

Install version 0.9.1 over the existing desktop application. Saved decks, owned cards, prompt history, assistant size preferences, desktop AI settings, provider preferences, and database backups remain compatible. No data migration is required.
